# Research and implementation plan

## Device facts verified over ADB

The TV reports model `MiTV-AXFR0`, codename `rango`, Android 11 (API 30), a 1280 × 720 interface at density 213, and `MemTotal: 1012412 kB` (about 1 GiB). The `/data` filesystem is 4.0 GiB, with about 2.0 GiB free at inspection. These are readings from this device, and are more useful than retail specifications for a different Redmi series. Netflix (`com.netflix.ninja`), YouTube (`com.google.android.youtube.tv`), and Xiaomi TV+ (`com.mitv.tvhome.mitvplus`) are installed. The original HOME is `com.google.android.tvlauncher/com.google.android.tvlauncher.MainActivity`.

The 1 GiB RAM figure is a reason to keep the launcher small. It does not imply that unused RAM must be emptied: Android keeps apps cached for faster return and reclaims memory when needed ([Android memory overview](https://developer.android.com/topic/performance/memory-overview)).

## What existing launchers show

[Free My TV](https://github.com/simbasjungles/free-my-tv) uses a lean Java/Canvas implementation and shows that a compact TV launcher is feasible. Its published memory improvement is a measurement from one TCL set and does not predict performance on this Redmi. Its Xiaomi package disable list includes Xiaomi TV+, which conflicts with this user's requirement, so this project does not copy that approach. [FLauncher](https://gitlab.com/flauncher/flauncher) uses Flutter. Still Home uses native Android Views and Java, with no runtime library dependency, to reduce startup and memory overhead on this 1 GiB TV.

## Design and implementation

1. **Home:** an exported `MAIN + HOME + DEFAULT` activity, plus a separate `LEANBACK_LAUNCHER` entry and TV banner. The Home button is routed by Android; an ordinary activity cannot intercept it ([Android Home key](https://developer.android.com/reference/android/view/KeyEvent), [TV app setup](https://developer.android.com/training/tv/get-started/create)).
   The top row has separate Apps, TV settings, and Launcher settings actions. The TV settings action uses Android's documented `Settings.ACTION_SETTINGS` implicit intent, which resolves to `com.android.tv.settings/.MainSettings` on this Redmi TV. Directly starting the intent requires no package-visibility `<queries>` entry ([Settings API](https://developer.android.com/reference/android/provider/Settings), [package-visibility use cases](https://developer.android.com/training/package-visibility/use-cases)).
2. **Apps:** query `LEANBACK_LAUNCHER` first and `LAUNCHER` second, with manifest `<queries>` declarations required by Android 11 package visibility ([package visibility](https://developer.android.com/training/package-visibility/declaring)). Explicit known packages cover Netflix, YouTube and [Xiaomi TV+](https://play.google.com/store/apps/details?id=com.mitv.tvhome.mitvplus). Launch the exported component Android reports; do not hard-code app activities.
3. **Visuals:** The runtime home screen follows the owner's revised reference, using their dusk lake image, a thin clock, three icon-labeled glass controls, and a six-card shelf with a raised blue focus state. The original Horizon shelf study remains in `design/mockups`. Wallpapers are bundled JPEGs or a personal image sent from the Mac; photos decode on a worker thread in RGB 565. Glass surfaces draw a small cached blurred crop aligned to the wallpaper, so D-pad focus changes never blur the live screen. This TV resolves Android document intents to a nonfunctional framework stub, so the personal-image workflow uses `scripts/send_wallpaper.py` and the installed debug app's `run-as` access. The transfer validates the image on the Mac, keeps at most 12 imports, and offers removal by holding OK on a photo in Settings.
4. **Screensaver:** register a `DreamService`, show the chosen wallpaper dimmed, and shift the clock slightly once per minute ([DreamService](https://developer.android.com/reference/android/service/dreams/DreamService)). This TV does not resolve `android.settings.DREAM_SETTINGS`, so `scripts/configure_screensaver.py` checks that the service is installed, saves the original secure setting in a TV-bound backup, selects Still Home's service, verifies it, and can restore the original value. Android still controls when it runs.
5. **Maintenance:** show actual storage/memory state and open system App info/storage tools. A normal app cannot clear other apps' caches: `CLEAR_APP_CACHE` is privileged ([permission reference](https://developer.android.com/reference/android/Manifest.permission)). Android also discourages third-party task killers as performance tools ([Android 14 process behavior](https://developer.android.com/about/versions/14/behavior-changes-all)).
6. **Deployment:** install via authenticated ADB over this LAN and test as an ordinary app. This firmware's Google TV HOME filter has priority 2 while a nonprivileged third-party app's positive priority is capped to 0 ([intent-filter reference](https://developer.android.com/guide/topics/manifest/intent-filter-element)). Setting the HOME role alone reports success but the Home key still opens Google TV. The TV blocks disabling its individual Home activity, so setup additionally uses `pm disable-user --user 0 com.google.android.tvlauncher`. This leaves Xiaomi TV+ and the rest of Android installed. Restore by enabling that package first, then setting the original HOME component. Both directions were verified on this TV. Xiaomi documents how to enable ADB debug on Mi TV ([Xiaomi support](https://www.mi.com/uk/support/article/KA-06513/)); Android documents ADB's authorization and connection model ([ADB guide](https://developer.android.com/tools/adb)).

## Device verification

The debug APK was built and installed on this TV. ADB key events exercised Home focus and D-pad navigation, the scrolling All apps grid with 21 launchable apps, hold-OK favorite changes, and return from Netflix, YouTube, and Xiaomi TV+ via the Home key. The new TV settings action opened `com.android.tv.settings/.MainSettings`; its Network & Internet screen exposed Wi-Fi choices, and the settings home showed Ethernet status. The separate Launcher settings action opened Still Home's preferences, and Back preserved toolbar focus. Built-in wallpaper changes, a Mac photo transfer and removal, screensaver preview and secure-setting selection, and the maintenance screen were checked on the device. The original Google TV Home setup was restored once and then Still Home was selected again. The TV is now left on Still Home. With version 0.2.0 open on Home, `dumpsys meminfo` showed 64,434 kB total PSS. One 10-key ADB navigation run after app loading showed a 10 ms median frame time and three missed frame deadlines across 100 frames. ADB injection reported high input latency, so this is a local diagnostic rather than a remote-control performance guarantee. Physical-remote key mapping and the firmware's natural screensaver idle trigger have not been independently timed.

## Limits

Still Home changes only the HOME experience. It cannot remove ads inside other apps, guarantee playback performance, force-stop arbitrary apps, or silently clear system caches. Xiaomi firmware might retain special keys that open PatchWall. The stock Google TV launcher package stays installed but is disabled for user 0 while Still Home is Home; this also removes Google TV launcher features until rollback. Xiaomi TV+ remains installed and enabled. Personal ADB installs remain permitted under Google's 2026 developer verification rules ([official FAQ](https://developer.android.com/developer-verification/guides/faq)).

## 0.3: the Free My TV rendering and features

The owner liked the 0.2 look and asked for the modern pieces of [Free My TV](https://github.com/simbasjungles/free-my-tv) on top of it: weather, a drawer under the shelf, glassy surfaces with reflections, subtle animation, customization, and a dynamic screensaver with an analog glass clock, without losing speed. Free My TV is MIT-licensed, so its code was lifted where it fit (see `THIRD_PARTY.md`).

1. **One Canvas.** `HomeView` replaces the view tree of 0.2. The layout stays the same (measured in a 1920×1080 space, scaled by the screen width), the layers are separate child views so only what changed is redrawn, focus moves with damped springs (`Spring`), and the frame callback sleeps when nothing moves. On Android 8 to 11 the hardware layers are off and shadows come from cached nine-slice bitmaps (`Shadows`), as Free My TV measured on a Mi Box 3.
2. **Glass without AGSL.** Free My TV's aurora and Liquid Glass are AGSL `RuntimeShader`s (Android 13+). This TV is Android 11. `Scene` keeps the shaders for newer devices and adds CPU paths: the aurora is `Frost`'s math in a 96×54 image, and the glass is the blurred wallpaper (`Backdrop.frost`/`glass`, built once off the UI thread) drawn through the rounded shape with a `BitmapShader`, plus a sheen and a rim gradient. A debug file (`files/debug-legacy`, see `Ui.debugFlag`) forces these paths on a newer device for testing.
3. **Weather.** `HomeData` is Free My TV's Open-Meteo client without the crypto prices and without a build-time config: the city is chosen on the TV through Open-Meteo's geocoding. The app now holds the INTERNET permission; it is used for nothing else, and turning Weather off stops all requests. The aurora's palette follows the fetched sunrise and sunset (`Shaders.sky`).
4. **Favorites.** The shelf list moved from `LauncherPrefs` to `Prefs.shelf` (migrated on first start). Reordering by holding OK is Free My TV's; pinning moved to the All apps sheet (hold OK), with a limit of 8.
5. **Screensaver.** `AmbientView` draws the glass disc with `Scene.liquid`, cached marks and numerals (`Recording`), hands with offset shadows and a sweeping second hand computed from the millisecond, at 30 frames a second. Photos use Free My TV's Ken Burns slide code; the aurora uses `Scene`. The clock group drifts on a 10-minute sine path.
6. **Verification.** Built on Windows with a portable JDK 17; exercised on a 1280×720 API 36 emulator with remote keys and screenshots (`design/screenshots/*-0.3.png`), on both the shader and the forced CPU paths, including live weather for Mumbai; then installed on the Redmi and measured there (see the README's Verified section).
7. **What the Redmi taught.** Its CPU is a 32-bit ARMv7 userland: the CPU aurora costs ~70 ms a step at 96×54, so it runs on a background-priority worker (`Ui.worker`) at 64×36 and 5 steps a second on Android 8–11, and not at all while a photo is the wallpaper. Workers at normal priority (banner decoding, wallpaper blurring, the aurora) starved the main thread for most of a second at start, so every worker is background priority. The first text shaped with each Inter variable-font instance cost the text engine ~700 ms on the first frame; the fonts are now warmed on a worker at app start and fitted labels are cached. Creating `TvInputManager` and decoding app icons were moved off the main thread (icons are cached as PNGs). Debug builds log any main-thread message over 48 ms and sample the main thread's stack when one runs past 150 ms (`App.watchMainThread`).
